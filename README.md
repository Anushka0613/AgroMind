# 🌾 AI-Powered Crop & Fertilizer Recommendation System

A machine learning + generative AI system that recommends the best crop for a
farmer's soil/climate conditions, diagnoses nutrient deficiencies, prescribes
a specific fertilizer, and explains all of it in plain language (optionally
in the farmer's own language) using an LLM.

---

## 1. Problem Statement

Farmers, especially smallholders, often lack easy access to agronomists and
end up choosing crops or applying fertilizer based on habit or guesswork
rather than actual soil/climate suitability. This leads to poor yields,
wasted fertilizer, and long-term soil degradation.

**Goal:** Given a soil test (N, P, K, pH) and local climate data
(temperature, humidity, rainfall), recommend:
1. The best-fit crop(s), with confidence scores.
2. A specific fertilizer plan to correct any nutrient gaps.
3. A short, farmer-friendly explanation of both — generated by an LLM.

---

## 2. System Architecture

```
                     ┌────────────────────────┐
   Soil + Climate --> │  Random Forest Model   │ --> Top crop + confidence
   (N,P,K,temp,       │  (crop_model.pkl)      │     + top-5 alternatives
   humidity,ph,        └────────────┬───────────┘
   rainfall)                        │
                                     v
                     ┌────────────────────────┐
                     │ Fertilizer Advisor      │ --> Nutrient gap analysis
                     │ (rule-based, data-      │     + specific fertilizer
                     │  driven nutrient        │       recommendation
                     │  profiles per crop)     │
                     └────────────┬───────────┘
                                     │
                                     v
                     ┌────────────────────────┐
                     │  GenAI Explainer        │ --> Plain-language
                     │  (Anthropic API, or     │     explanation, any
                     │   template fallback)    │     language
                     └────────────┬───────────┘
                                     │
                                     v
                       Streamlit web app (app.py)
```

**Key design decision — why the fertilizer engine is rule-based, not a
second classifier:** public fertilizer-prediction datasets (Kaggle
`gdabhishek/fertilizer-prediction` and similar) only cover ~7-8 crops and
~100-200 rows — far narrower than the 22-crop recommendation model. Instead
of bolting on a mismatched dataset, we derive each crop's *ideal* N, P, K and
pH range directly from the same 2,200-row training data (mean ± std per
crop), then compare the farmer's actual soil test against that profile. This
generalizes to all 22 crops with zero extra data collection, and is fully
explainable — which matters more in agriculture (and finance/healthcare)
than raw accuracy.

## 3. Dataset

**Crop Recommendation Dataset** (2,200 rows, 22 crops, 7 features, no missing
values):

| Column | Description |
|---|---|
| N | Nitrogen content in soil (kg/ha) |
| P | Phosphorus content in soil (kg/ha) |
| K | Potassium content in soil (kg/ha) |
| temperature | °C |
| humidity | Relative humidity (%) |
| ph | Soil pH |
| rainfall | mm |
| label | Crop (target) — 22 classes, 100 samples each |

Crops covered: rice, maize, chickpea, kidneybeans, pigeonpeas, mothbeans,
mungbean, blackgram, lentil, pomegranate, banana, mango, grapes, watermelon,
muskmelon, apple, orange, papaya, coconut, cotton, jute, coffee.

## 4. Algorithms Compared

| Model | Test Accuracy | Weighted F1 | 5-fold CV Accuracy |
|---|---|---|---|
| Logistic Regression | 95.0% | 0.950 | 97.2% |
| KNN (k=5) | 97.7% | 0.977 | 97.7% |
| Decision Tree | 98.0% | 0.979 | 98.4% |
| **Random Forest (selected)** | **99.3%** | **0.993** | **99.5%** |
| SVM (RBF) | 98.4% | 0.984 | 97.4% |
| XGBoost | 98.9% | 0.989 | 99.0% |

Random Forest was selected as the production model (best accuracy, robust
across folds, gives feature importances for free). See
`models/model_comparison.csv`, `models/confusion_matrix.png` and
`models/feature_importance.png` for the full evaluation artifacts.

## 7. How to Run

```bash
# 1. Install dependencies
pip install -r requirements.txt

# 2. (Already done, but to retrain from scratch)
python src/train_crop_model.py
python src/eda.py

# 3. Launch the app
streamlit run src/app.py
```

To enable the GenAI explanation with a real LLM, paste an Anthropic API key
into the sidebar field in the app (get one at console.anthropic.com). Without
a key, the app still works fully — it falls back to a clear, deterministic
template explanation.

## 8. Feasibility & 16-Day Build Plan (as actually executed)

| Days | Task |
|---|---|
| 1–2 | Problem scoping, dataset sourcing & cleaning, EDA |
| 3–5 | Train & compare 6 algorithms, pick best, evaluate (confusion matrix, feature importance) |
| 6–8 | Design & build the rule-based fertilizer advisor (nutrient-gap logic) |
| 9–10 | Build the GenAI explanation layer (prompt design + offline fallback) |
| 11–13 | Build the Streamlit UI, wire all three layers together |
| 14–15 | Testing edge cases (extreme soil values, missing API key, all 22 crops), polish UI |
| 16 | Documentation, README, demo prep |

**Difficulty:** Low–Moderate. Tabular data, no GPU required, all libraries
are mainstream. The most time-consuming part is prompt-tuning the GenAI
layer and making the UI feel farmer-friendly rather than "data science-y."

**Impact:** Directly usable by an agri-extension worker or a farmer with a
smartphone; encourages precision fertilizer use (cost savings + reduced
environmental runoff from over-fertilization).

## 9. Limitations & Future Work

- The nutrient "ideal profile" is derived from a single aggregated dataset
  (India-centric climate ranges); it should be recalibrated with regional
  soil-survey data before real-world deployment.
- No image-based soil/leaf analysis yet — could be added (see the earlier
  crop-disease-detection project) to make this a full "point phone camera at
  field, get full diagnosis" tool.
- Fertilizer *quantities* (kg/acre) are not yet computed — only qualitative
  guidance (which fertilizer, not how much). A dosage model is a natural v2.
- Add a chatbot mode so farmers can ask free-form follow-up questions
  ("what if I can't get DAP, what's a substitute?").
